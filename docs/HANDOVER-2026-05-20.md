## The strategic state

### Yesterday's open question (now answered)

> *"is it worth just starting with a fresh translation? we can keep the ink part and integrate after?"*

**Audit's answer: yes, with constraints.** Specifically: scoped rewrite into `src-ts-v2/` with 2-week kill-criterion. See `docs/adr/0001-rewrite-vs-patch.md` Decision Outcome section.

### Headline findings driving the recommendation

1. **TS backend is 74% larger than Python source** (7,295 vs 4,186 LOC) for ostensibly the same functionality. That extra weight is not type signatures or error classes — it's defensive plumbing around `any`-typed boundaries, duplicate mapping shims, identity type aliases (`VideoRow = Video`), and ceremony. A clean rewrite targets ~5,500-6,000 TS LOC — **smaller than current**.
2. **Same bug class keeps shipping.** Five "stubs marked complete" confirmed (PlaylistAdd, PlaylistRemove, savePlaylistItem, getAnalysisData, PlaylistAddMine/Sync field mismatch). All five share root cause: writer never verified the contract end-to-end. Tests pass because mocks return the expected shape. This is **one missing discipline expressed five times**, not five separate bugs. Patching closes one; rewriting (with Zod + branded `VideoId`/`PlaylistId`) closes the class.
3. **The Ink layer is the keeper.** 3,727 LOC, zero anti-patterns, 20-method contract surface with the backend (mapped in REWRITE_AUDIT.md §4). Any backend re-implementation just has to satisfy those 20 signatures.
4. **Python source is trustworthy as porting target** but has 12 of its own issues (catalogued in `PORT_PLAN.md` § "Python source issues — remediation map"). Each issue has explicit disposition: DO NOT PORT / REDESIGN / FIX IN PLACE / NOT PORTED / DOCUMENT AS KNOWN GAP. No silent inheritance.
5. **Test coverage is misleading.** Claimed "75% / 130 tests" — actual count is 235 tests. But 4 critical files have **zero** coverage: `PostExtractionMenu`, `HTMLReportGenerator`, `VideoCommands`, `cache`, `playlistResolver`. The test suite clusters on the modules the migration team felt safe in, abandons where the user contract actually lives.

### The recommended path (per ADR 0001)

**v2 scope (FROZEN):**
- `init`, `playlist {discover, list, add, remove}`, `extract playlist <id>`, `report playlist <id>`
- Out of scope for v2: REPL mode, `--all`, single-video commands, `--search` multiselect, Whisper de-Python, AI analysis re-port (all re-land post-ship, one at a time)

**Wave structure:**
- Week 1: Contract layer (Zod schemas + branded types + `withTransaction<T>` mandatory)

- Week 3: Pipeline (extractPlaylist + live test against real account)

**Kill criterion:** If end of Week 2 the new repository layer is not green-tested and integrated, abandon v2 and execute the patch fallback (5 commits, ~24h, in REWRITE_AUDIT.md §10).

## Critical new finding (worth re-reading)

`src-ts/commands/PlaylistCommands.tsx:663-998`

Both `PlaylistAddMine` and `PlaylistSync` read `p.playlistId` on objects typed as `YouTubePlaylist`. The actual field on `YouTubePlaylist` (defined `src-ts/api/types.ts:9`) is `id`. Because the objects are typed `any`, TypeScript doesn't catch this. Affected call sites (per silent-failure-hunter agent):

- Line 690: dedup check `existingIds.has(p.playlistId)` — always returns `false` since `playlistId` is `undefined`
- Line 705: auto-select filter
- Line 763: `performBulkAdd` skip check
- Line 770: `repo.createOrUpdate({ playlist_id: playlist.playlistId, ... })` — writes `playlist_id: undefined`
- Lines 826, 828, 931, 934, 983, 1065: same field-access pattern in sync flow

`PlaylistDiscover` (line 180) correctly uses `playlist.id`, confirming this is a drift, not intent.

Affected commands: `metube playlist add-mine` and `metube playlist sync`. Both silently produce corrupt DB rows or no-ops depending on `createOrUpdate`'s handling of `undefined` PK. **Has never worked end-to-end.**

This is the 5th confirmed instance of the "stubs marked complete" pattern. It's why the audit recommends rewrite over patch — the pattern isn't a list of bugs to fix, it's a missing discipline.

## Conventions & gotchas (from CLAUDE.md + this session)

### Local-only work, do not push

User explicitly set this directive yesterday. Still in effect. 18 commits ahead of origin are deliberate. **Re-ask before any `git push`**.

### REVIEW gate discipline

AI moves work to REVIEW; human approves REVIEW → DONE. Currently `_kanban.md` REVIEW has 13 items (9 from yesterday + 4 added today). The audit itself is one of them — it's the artifact for owner review.

### Post-commit hook auto-syncs kanban

`.git/hooks/post-commit` runs `kanban-sync _kanban.md` after any commit touching `_kanban.md`. No commit fired this session, so no sync. Next commit that touches `_kanban.md` will sync the new items to GH Project #9.

### `gh` CLI at Windows path

When using `gh` via Bash tool: `"/c/Program Files/GitHub CLI/gh.exe"`. `which gh` from MINGW64 returns nothing despite the binary existing.

### Ink components need a TTY

`useInput` from Ink panics without a real terminal. Running metube commands via the Bash tool causes React reconciler errors. To verify auth or test API, write a direct-script using `googleapis` directly — don't try to invoke `metube` from a non-TTY shell.

### Live test as signal-of-done

Yesterday's bug-find lesson, baked into ADR 0001's recommended discipline: **bugs that survive type-check + lint + tests are caught only by exercising the path against real services**. The audit recommends weekly live-test sessions if/when v2 starts. "Compiles clean" is necessary but not sufficient.

### The `stubs-marked-complete` instinct (project-scoped)

A learned instinct now exists at `~/.claude/homunculus/projects/f0004604bb82/instincts/personal/stubs-marked-complete.yaml`. When working in `src-ts/`, treat any of these as red flags:

- Comments like "This would..." / "For now, just log" / "TODO: implement"
- `: any` on a critical-path public API
- A repository declared in `models.ts` with no `.ts` file (Tag, ExtractionJob, AIAnalysis are currently missing)
- A try/catch in a write path that catches and returns/logs without re-throwing
- `console.error` or `console.log` in production code (forbidden by CLAUDE.md)
- Field-name access on `any`-typed objects

If you see one: open the file, verify the called downstream method exists AND is implemented AND has behavioral test coverage. Log to `_kanban.md` REVIEW with `[Stub-watch]` tag if any of those fail.

### Sensitive files (unchanged from prior handovers)

`tokens.json`, `client_secret.json`, `.env`, `data/`, `reports/`, `logs/` — all gitignored. Never edit, never commit, never print contents. If you need to inspect token shape, use `process.env` checks or `len()`/boolean presence — never the value.
